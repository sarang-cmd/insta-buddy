Privacy Policy.

Draft prepared 26 October 2026. Not legal advice. No data controller or effective date has been named.

1. About this draft

This draft describes the code in the Insta Buddy repository at the time it was prepared. It covers the web app, the desktop app and this static marketing site. It does not cover a hosted backend, because this repository does not include one. It is not a finished policy and should be reviewed by a qualified lawyer before launch.

The data controller or project owner has not been identified yet: [Controller legal name and address]. A working privacy contact is also missing: [Contact email].

2. What the app processes

When you add files, the app reads the image, available EXIF metadata and file timestamps. It creates previews, analysis scores, similarity hashes, suggested edits, captions and export files. In the current version, photos and analysis results are held in memory for the active session. Refreshing the page or using New trip clears that session. There is no local photo database in version 1.

AI settings are stored in browser local storage in the web build. In the web build, API keys are held in memory only. In the desktop build, keys are stored in an encrypted vault in the application data directory, using OS encryption where available.

3. When information leaves your device

Sorting, scoring, grouping, editing, caption drafting and export run on your device. Information can leave your device when you deliberately enable an optional AI feature. Depending on the feature and your settings, that request may include text, photo metadata or images. Sending photos to a cloud provider requires a separate image upload opt-in. Local providers such as Ollama or LM Studio can receive requests on your own machine.

The desktop app sends AI requests from its main process and applies an HTTPS guard, with a loopback HTTP exception for local providers. The web build keeps keys in memory for the current tab. The app does not upload your photo library by default.

4. What this repository does not include

At the time of writing, the repository contains no backend service, no user account system, no analytics SDK and no advertising SDK. The marketing site code sets no cookies of its own. A hosting provider may still create access logs when it serves these static files. That provider and its log retention period must be documented here: [Hosting provider and log retention].

5. Website data

This site is built from static HTML, CSS, JavaScript, fonts and screenshots. It does not include a contact form, analytics script or embedded third-party tracker in its own code. If a content delivery network, hosting provider or external link is added later, this section must be updated before deployment.

6. Retention

Photos, previews and edits remain in memory until the session ends or you clear the trip. AI settings remain in local storage until you clear site data. Desktop API keys remain in the encrypted vault until they are removed or the application data is deleted. Exported ZIP files remain on your disk until you delete them. Provider-side retention for optional AI requests is controlled by the provider you selected and must be checked in that provider's policy.

7. Your choices

You can use the app without AI, keep image upload off, choose which photos to export, clear local site data and close the tab to end a session. The working demo can be used with the built-in generated photos instead of your own files.
